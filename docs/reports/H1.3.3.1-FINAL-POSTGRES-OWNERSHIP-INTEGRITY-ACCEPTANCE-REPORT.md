## 3. Root Cause Analysis of Actions Run #8 (`44942561737`)

In GitHub Actions Run #8, the job successfully executed:

- Prisma schema synchronization (`npx prisma db push --skip-generate`).
- Native PostgreSQL connectivity preflight.

- Ownership trigger creation and verification (`h1-3-3-ownership-monotonicity-trigger.sql` and `h1-3-3-verify-ownership-trigger.sql`).

It then invoked Vitest for the four integration test suites. The failure occurred inside `test/integration/postgres-wallet-ownership.test.ts` during `beforeAll()`:
```
ERROR: cannot insert multiple commands into a prepared statement
```

### Technical Root Cause
Prisma Client's query engine utilizes PostgreSQL's extended query protocol (`Parse`, `Bind`, `Execute`). When executing raw SQL via `prisma.$executeRawUnsafe()`, Prisma submits the query string as a prepared statement. Under PostgreSQL specifications, a prepared statement may only contain a single SQL command. When multiple commands separated by semicolons are passed (such as `CREATE OR REPLACE FUNCTION ...; DROP TRIGGER ...; CREATE TRIGGER ...;`), PostgreSQL rejects the call with error code `25P02`/`42601`. Because `isPostgresLive` was true in CI, this rejection threw an unhandled error in `beforeAll()`, aborting setup and causing Vitest to mark all 12 tests in the suite as skipped.

The CI verification gate strictly requires `TOTAL=50, PASSED=50, FAILED=0, SKIPPED=0`. With 38 passed and 12 skipped, the gate terminated with exit code 1.

## 5. Final SQL Trigger Semantics

File: `prisma/sql/h1-3-3-ownership-monotonicity-trigger.sql`

```sql
CREATE OR REPLACE FUNCTION trg_enforce_claim_invitation_monotonicity()
RETURNS TRIGGER AS $$
BEGIN
  -- Deletion protection: consumed ownership records cannot be deleted
  IF TG_OP = 'DELETE' THEN
    IF OLD."consumedAt" IS NOT NULL OR OLD."claimedByUserId" IS NOT NULL THEN
      RAISE EXCEPTION 'claim_invitations deletion violation: consumed ownership records cannot be deleted'
        USING ERRCODE = '23514'; -- check_violation
    END IF;
    RETURN OLD;
  END IF;

  -- Initial state on INSERT: newly created invitations must begin unclaimed
  -- Rejects direct insertion of already-claimed or inconsistent records
  IF TG_OP = 'INSERT' THEN
    IF NEW."consumedAt" IS NOT NULL OR NEW."claimedByUserId" IS NOT NULL THEN
      RAISE EXCEPTION 'claim_invitations initial state violation: newly inserted invitations must be unclaimed (consumedAt and claimedByUserId must both be NULL)'
        USING ERRCODE = '23514'; -- check_violation
    END IF;
    RETURN NEW;
  END IF;

  -- The following immutability and paired-state rules apply to UPDATE operations
  IF TG_OP = 'UPDATE' THEN
    -- Invariant 0: Paired ownership-state invariant (both NULL or both NOT NULL)
    IF (NEW."consumedAt" IS NULL) IS DISTINCT FROM (NEW."claimedByUserId" IS NULL) THEN
      RAISE EXCEPTION 'claim_invitations ownership state violation: consumedAt and claimedByUserId must both be NULL or both be NOT NULL (paired ownership state)'
        USING ERRCODE = '23514'; -- check_violation
    END IF;

    -- Invariant 1: credentialId cannot be altered
    IF OLD."credentialId" IS DISTINCT FROM NEW."credentialId" THEN
      RAISE EXCEPTION 'claim_invitations ownership violation: credentialId is immutable once created (attempted to change % to %)',
        OLD."credentialId", NEW."credentialId"
        USING ERRCODE = '23514'; -- check_violation
    END IF;

    -- Invariant 2: Once consumed, consumedAt cannot be cleared or modified
    IF OLD."consumedAt" IS NOT NULL THEN
      IF NEW."consumedAt" IS NULL THEN
        RAISE EXCEPTION 'claim_invitations ownership violation: consumedAt cannot be reset to NULL once consumed'
          USING ERRCODE = '23514'; -- check_violation
      END IF;
      IF OLD."consumedAt" IS DISTINCT FROM NEW."consumedAt" THEN
        RAISE EXCEPTION 'claim_invitations ownership violation: consumedAt is immutable once set (attempted to change % to %)',
          OLD."consumedAt", NEW."consumedAt"
          USING ERRCODE = '23514'; -- check_violation
      END IF;
    END IF;

    -- Invariant 3: Once assigned, claimedByUserId cannot be cleared or reassigned
    IF OLD."claimedByUserId" IS NOT NULL THEN
      IF NEW."claimedByUserId" IS NULL THEN
        RAISE EXCEPTION 'claim_invitations ownership violation: claimedByUserId cannot be cleared once assigned'
          USING ERRCODE = '23514'; -- check_violation
      END IF;
      IF OLD."claimedByUserId" IS DISTINCT FROM NEW."claimedByUserId" THEN
        RAISE EXCEPTION 'claim_invitations ownership violation: claimedByUserId is immutable once assigned (attempted to change % to %)',
          OLD."claimedByUserId", NEW."claimedByUserId"
          USING ERRCODE = '23514'; -- check_violation
      END IF;
    END IF;
  END IF;

  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

DROP TRIGGER IF EXISTS trg_claim_invitation_monotonicity ON "claim_invitations";

CREATE TRIGGER trg_claim_invitation_monotonicity
BEFORE INSERT OR UPDATE OR DELETE ON "claim_invitations"
FOR EACH ROW
EXECUTE FUNCTION trg_enforce_claim_invitation_monotonicity();
```

## 6. Paired-State Enforcement & Initial State Validation

### Initial State on INSERT
Newly created invitations must begin in the unclaimed state:
$$\text{consumedAt} = \text{NULL} \land \text{claimedByUserId} = \text{NULL}$$
Direct insertion of already-claimed records or one-sided records bypasses the atomic claim lifecycle and is rejected with SQLSTATE `23514`.

### Paired State on UPDATE
The legitimate claim transition occurs via `UPDATE`:
- **Before:** `consumedAt IS NULL AND claimedByUserId IS NULL`
- **After:** `consumedAt IS NOT NULL AND claimedByUserId IS NOT NULL`
Both fields must be populated in the same atomic statement. One-sided updates (`consumedAt` set without `claimedByUserId`, or `claimedByUserId` set without `consumedAt`) violate:
$$(NEW."\text{consumedAt}" \text{ IS NULL}) \text{ IS DISTINCT FROM } (NEW."\text{claimedByUserId}" \text{ IS NULL})$$
and are rejected with SQLSTATE `23514`.

---

## 7. Ownership Immutability Behavior

Once established, ownership is permanent and monotonic:
1. `credentialId` is immutable: Any attempt to mutate `credentialId` raises SQLSTATE `23514`.
2. `consumedAt` is permanent: Once `OLD."consumedAt" IS NOT NULL`, setting `NEW."consumedAt"` to `NULL` or changing its timestamp raises SQLSTATE `23514`.
3. `claimedByUserId` is permanent: Once `OLD."claimedByUserId" IS NOT NULL`, clearing it to `NULL` or reassigning it to another user raises SQLSTATE `23514`.

---

## 8. Deletion & Cascade-Protection Policy

### Consumed Record Deletion Defense
A row-level `BEFORE DELETE FOR EACH ROW` trigger intercepts all deletion operations on `claim_invitations`:
- If `OLD."consumedAt" IS NOT NULL OR OLD."claimedByUserId" IS NOT NULL`, it raises SQLSTATE `23514`.
- Unconsumed invitations (`consumedAt IS NULL AND claimedByUserId IS NULL`) may be deleted normally.

### Cascade Deletion Defense Matrix
| Deletion Path | Mechanism | Behavior | Outcome |
| :--- | :--- | :--- | :--- |
| Direct `ClaimInvitation` delete | `DELETE FROM claim_invitations` | Blocked by `trg_claim_invitation_monotonicity` | SQLSTATE `23514` |
| Parent `CredentialRecord` delete | Cascade delete to child invitations | Row-level delete on child fires trigger | SQLSTATE `23514`, transaction aborts |
| Parent `Tenant` delete | Cascade delete to credentials & invitations | Row-level delete on child fires trigger | SQLSTATE `23514`, transaction aborts |
| Owner `User` delete | Foreign key `claimedByUserId` | Enforced by PostgreSQL foreign key `ON DELETE RESTRICT` | SQLSTATE `23503` (`foreign_key_violation`) |
| Soft Credential Revocation | `UPDATE credential_records SET state = 'REVOKED'` | Updates record state without touching claim invitations | Allowed; claim record intact |
