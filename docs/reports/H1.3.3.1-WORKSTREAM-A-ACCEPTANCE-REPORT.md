## 1. Executive Summary

In accordance with the **CREDVAIL Repository Audit & Forward Engineering Roadmap** (Document version 1.0, Workstream A), this audit and implementation resolved the latent teardown and fixture conflicts in the PostgreSQL integration test suite:

1. **Suite Teardown Monotonicity Conflict Resolved (`test/integration/postgres-claim-concurrency.test.ts`):**  
   The concurrency suite previously attempted a blanket cascade deletion of all claim invitations (`prisma.claimInvitation.deleteMany({ where: { tenantId } })`), followed by credentials, tenants, and users. In live PostgreSQL, redeemed claim invitations are protected by the trigger `trg_claim_invitation_monotonicity` which throws SQLSTATE `23514` (`CRV_INTEGRITY_ERR_CONSUMED_INVITATION_IMMUTABLE`) on any attempted `DELETE` of a consumed record. Deleting the parent user also fails due to the foreign key constraint `claimedByUser User? @relation(fields: [claimedByUserId], references: [id], onDelete: Restrict)`. The teardown has been corrected to only delete unconsumed invitations (`consumedAt: null, claimedByUserId: null`), preserving consumed ownership records and their dependencies within the ephemeral integration container.

2. **Foreign Key Integrity Fixtures Corrected (`test/integration/postgres-wallet-ownership.test.ts`):**  
   In test `H133-08`, both the duplicate `tokenHash` verification and step `5f` (legitimate pending invitation insertion) previously passed unseeded random UUIDs as `credentialId`. Because `ClaimInvitation` enforces a foreign key constraint referencing `CredentialRecord.credentialId`, insertions into `claim_invitations` without a corresponding `CredentialRecord` fail with foreign key violation `23503`. Both locations now seed genuine `CredentialRecord` fixtures first, guaranteeing that:
   - Step `5f` inserts cleanly and transitions atomically to claimed in step `5g`.
   - The duplicate `tokenHash` test isolates and validates the unique constraint violation (`23505`) without triggering foreign key errors.
