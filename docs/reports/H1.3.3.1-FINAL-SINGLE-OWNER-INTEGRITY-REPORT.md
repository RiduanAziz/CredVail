## 3. Final Partial Unique Index Definition

File: `prisma/sql/h1-3-3-single-owner-index.sql`

```sql
CREATE UNIQUE INDEX IF NOT EXISTS "claim_invitations_one_consumed_owner_per_credential_uq"
ON "claim_invitations" ("credentialId")
WHERE "consumedAt" IS NOT NULL
  AND "claimedByUserId" IS NOT NULL;
```

### Invariant & Schema Audit:
- **Table Name:** `claim_invitations` (mapped via Prisma `@@map("claim_invitations")`).
- **Indexed Column:** `"credentialId"` (String, foreign key to `credential_records.credentialId`).
- **Predicate:** `WHERE "consumedAt" IS NOT NULL AND "claimedByUserId" IS NOT NULL`.
- **Properties:**
  - Multiple pending unconsumed invitations (`consumedAt IS NULL`) are permitted, allowing issuers to re-send or replace claim tokens.
  - Anonymous invitations (`claimedByUserId IS NULL`) are excluded.
  - Exactly one consumed, authenticated ownership record can exist for any physical credential.

## 4. Proof of All Claim-Consumption Paths

Comprehensive codebase audit for all writes to `consumedAt`, `claimedByUserId`, and `claimedByHolderDid`:

### 4.1 Primary Path: `ClaimInvitationRepository.redeemInvitationTransaction()`
- **Mechanism:** PostgreSQL transaction (`RepeatableRead` / `Serializable`).
- **Pre-check:** Queries inside transaction for existing consumed owner (`credentialId, consumedAt != null, claimedByUserId != null`).
- **Database Lock:** Executes conditional `updateMany` matching `id`, `tokenHash`, `tenantId`, `certificateNumber`, `consumedAt: null`, and `expiresAt > consumedAt`.
- **Constraint Backstop:** If two concurrent claims race past the pre-check, PostgreSQL's partial unique index raises `23505 (unique_violation)`.
- **Atomic Rollback:** If any error or downstream failure occurs, the entire transaction rolls back; `consumedAt` and `claimedByUserId` remain `NULL`.

### 4.2 Legacy Mutation APIs: `consumeAtomic()` and `markConsumed()`
- **Status:** **Deprecated**. Both methods are annotated `@deprecated` and instructed to use `redeemInvitationTransaction`.
- **Production Defense:**
  - In production (`NODE_ENV === "production"`) or under `REQUIRE_POSTGRES_INTEGRATION=true`, memory fallback is prohibited.
  - Prior to update, the method queries for an existing consumed owner for `credentialId`. If found, throws `CredentialAlreadyClaimedError`.
  - Catches database unique violations on the partial index and translates them into typed `CredentialAlreadyClaimedError`.
  - Cannot establish a second owner or bypass the partial unique index.

## 5. Exact Unique-Error Classification Behavior

### 5.1 Classification Logic in `ClaimInvitationRepository`
```typescript
function isSingleOwnerIndexViolation(err: any): boolean {
  if (!err) return false;
  if (typeof err.message === "string") {
    const msg = err.message.toLowerCase();
    if (msg.includes("claim_invitations_one_consumed_owner_per_credential_uq")) return true;
  }
  if (err.code === "P2002") {
    const target = err.meta?.target;
    if (Array.isArray(target) && target.includes("credentialId")) return true;
    if (
      typeof target === "string" &&
      (target.includes("credentialId") ||
        target.includes("claim_invitations_one_consumed_owner_per_credential_uq"))
    ) {
      return true;
    }
  }
  return false;
}
```

### 5.2 Unrelated Unique Violation Isolation
To avoid incorrectly mapping unrelated unique constraint violations (e.g. duplicate `tokenHash`, recipient email uniqueness, or audit log collisions) to `CREDENTIAL_ALREADY_CLAIMED`:
1. If `isSingleOwnerIndexViolation(err)` is true, throws `CredentialAlreadyClaimedError`.
2. If `err` is a generic unique violation (`P2002` or `23505`) without explicit index metadata:
   - Performs a safe post-failure query on `credentialId` to inspect if another consumed claim exists.
   - If an existing consumed owner exists, throws `CredentialAlreadyClaimedError`.
   - If no existing consumed owner exists, **rethrows the original error untouched**.
3. In `isRetryableTransactionConflict(err)`, `isAnyUniqueViolation(err)` returns `false`, ensuring unique conflicts are never retried.
4. The losing claim rolls back completely; the losing invitation remains unconsumed (`consumedAt IS NULL`).
5. The claim API maps `CredentialAlreadyClaimedError` to HTTP 409 with body:
   ```json
   {
     "success": false,
     "error": "Credential has already been claimed by another account",
     "code": "CREDENTIAL_ALREADY_CLAIMED"
   }
   ```

## 8. Presentation Authorization Order

Endpoint: `POST /api/v1/wallet/present`

### Verification Hierarchy:
```
1. Authenticate Session (HTTP 401 on failure)
2. Parse Presentation & Challenge Nonce (HTTP 400 on malformed payload)
3. Extract and Normalize All Embedded VCs (Array check, string id check)
4. MANDATORY PRE-FLIGHT DURABLE OWNERSHIP CHECK:
   - For EACH embedded VC in presentation:
     - Query WalletService.userOwnsCredential(session.sub, vc.id, vc.certificateNumber)
     - On Database Outage -> Return HTTP 503 (Nonce Preserved)
     - On Any Unowned VC -> Return HTTP 403 (Nonce Preserved)
5. Cryptographic Presentation Verification:
   - VerificationService.verifyPresentation()
   - Atomically consumes challenge nonce in PostgreSQL
   - Verifies holder ECDSA NIST P-256 signature and audience
6. Return HTTP 200 on Success, HTTP 400 on Invalid Signature
```

### Replay Defense Invariant:
Because Step 4 precedes Step 5, any unauthorized, unowned, or foreign presentation is rejected with HTTP 403 *before* the challenge nonce is touched. The verifier's challenge nonce remains unconsumed in PostgreSQL.

## 13. Remaining Risks and Production Migration Requirements

### 13.1 Production Schema Audit Regarding `ClaimInvitation`
- The baseline `ClaimInvitation` model does **not** contain a `status` column. 
- Consumption state is determined strictly by:
  - Unconsumed: `consumedAt IS NULL` and `claimedByUserId IS NULL`.
  - Consumed: `consumedAt IS NOT NULL` and `claimedByUserId IS NOT NULL`.

### 13.2 Remediation Policy for Pre-Existing Duplicates
If `h1-3-3-data-integrity-check.sql` detects duplicates on a production database:
1. **Never Automatically Assign Earliest Timestamp:** An earlier timestamp might represent a test artifact or race anomaly.
2. **Investigation Protocol:** Every duplicate row must be evaluated by a human security auditor against:
   - Tenant audit logs (`AuditLog` records for `resourceType: "claim_invitation"`).
   - Recipient email and identity verification records.
   - Associated issuance batch.
3. **Safe Remediation (Never reset `consumedAt` to NULL):**
   - Resetting `consumedAt = NULL` reopens the invitation token to replay attacks.
   - Remediation must nullify the duplicate claim without permitting re-consumption (for instance, setting `tokenHash` to a spent tombstone or deleting the duplicate invitation row with explicit management approval and an immutable audit log).
4. **Zero-Downtime Index Creation:** On live production tables with high concurrent traffic, use:
   ```sql
   CREATE UNIQUE INDEX CONCURRENTLY IF NOT EXISTS "claim_invitations_one_consumed_owner_per_credential_uq"
   ON "claim_invitations" ("credentialId")
   WHERE "consumedAt" IS NOT NULL AND "claimedByUserId" IS NOT NULL;
   ```
